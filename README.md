# お好み焼き、ひっくり返せ！

単一ファイルHTMLのミニWebゲーム（Three.js製・3D）。Muse VM上のClaude Codeが試作し、2026-11-21に継続開発のためMac miniへ引き継いだ。

## 遊び方（ゲームの流れ）

0. **タイトル画面**：鉄板で焼けるお好み焼きをカメラがゆっくり回って見せる。「はじめる」で開始（このタップで音声を有効化）
1. **生地を注いで広げる**：ボウルから長押しで生地を落とし、ドラッグで円く広げる。大きさはプリセットではなく、プレイヤーの操作で直径と厚さが決まる（厚さ＝体積÷面積を実時間表示）
2. **焼く**：焼き加減が色で進む。豚バラ3枚は焼く前に生地の上に置かれる
3. **ひっくり返す**：フリックの速さと角度で成否が決まる。失敗すると具材（千切りキャベツ・豚バラ・イカなど）が判別できる形で派手にぶちまける
4. **裏面を焼く→仕上げ**：ソース・マヨ・鰹節・青のりは自由にかけられて採点なし（ご褒美時間）

右上の消音ボタン（スピーカーの絵）は全画面に出ていて、いつでも音を消せる（ユーザー要望）。設定はブラウザに覚えておく（`localStorage` の `oko.muted`。保存できない環境では毎回「音あり」から始まる）。消音は全部の音が通る master の音量を 0 にするだけで、ゲームの進行には影響しない。ボタンの分、上部のタイトル文字を 6.9→5.8（×--u）に縮め、完成写真を少し下げた。

大失敗の採点画面は、ぶちまけた具材（いちばんおもしろい所）が画面キャプチャでも見えるよう、結果シートを小さくする（ユーザー要望）。見出しの横に点数、小さいグラフの横に数値を並べ、シートは画面の約35%（成功・惜しいときは約60%のまま）。カメラ（`camView('mess')`）も鉄板が画面の上寄りに収まる位置にしている。成功・惜しいときの採点画面は、カメラ（`camView('landed')`）を着地したお好み焼き（焼き面が上）に向け、結果シートの上の空きに大きく映す。距離はお好み焼きの直径に合わせて変わる（以前は空中を見たままで、上半分が真っ黒だった）。

「タイトルへ」ボタンは、ラウンドが終わる画面にだけ置く：完成写真の画面と、大失敗のときの採点画面。成功・惜しいときの採点画面（まだ裏面を焼く途中）には出さない（ユーザー指定）。再挑戦は採点画面の「もう一度」（大失敗時）または完成写真の「もう一度焼く」。

## 構成

- `src/logic.js` — 純ロジック（サイズ計算、焼き加減と色、フリック判定窓、判定、スコア）。ブラウザ非依存で単体テスト可能
- `src/game.html` — 画面・Three.jsシーン・入力・音（WebAudio合成）
- `public/` — 公開ルートにそのまま置くファイル（webgame スキルの決まり）。公開時に中身を `index.html` と同じフォルダ（`dist/<slug>/`）へコピーし、`./favicon.svg` などで取れるようにする
  - `public/favicon.svg` — ファビコン（銀のヘラと木の柄。背景透過：ユーザー指定。暗いタブでも沈まないよう外側に明るい縁）
  - `public/ogp.png` — SNS共有用のOGP画像（1200×630）。`npm run ogp`（`tools/ogp/make-ogp.mjs`）で作り直せる（ビルド済みの `dist/okonomiyaki/index.html` を撮る。作り直したら再ビルドで dist にも反映）
  - `public/apple-touch-icon.png` — iPhone ホーム画面用 180px。`favicon.svg` を背景透過のまま書き出したもの（ユーザー指定。iOS のホーム画面では透過部分が黒く表示されることは承知のうえ）。SVG を変えたら作り直す
- `build.js` — `src/` と Three.js r187 を単一ファイルの `index.html` に組み立て、`dist/okonomiyaki/` に出力する。毎回 `dist/` を空にしてから、`public/` の中身も同じフォルダにコピーする（ファビコンは埋め込まず `./favicon.svg`・`./apple-touch-icon.png` で参照）
- `dist/okonomiyaki/` — 完成品（ビルドで生成。`index.html` は単一ファイル・9:16。favicon・OGP画像が同じフォルダに並ぶ）。遊ぶときはこの `index.html` を開く。公開時はこのフォルダをそのまま配信する
- `tools/ogp/make-ogp.mjs` — OGP画像の生成。実際のゲームを Chrome で開き、注いで広げ（540ml→19cm）、こんがりで成功フリック → 宙を舞う瞬間を UI を隠して撮り、0.8倍にしてお好み焼きを右に置き、タイトル・一言・URLを左に重ねる。乱数は固定しているが撮る瞬間がわずかにずれるため、毎回少し違う絵になる
- `tests/logic.test.js` — ロジックの単体テスト（23件）
- `tests/screens.js` — Playwrightで通しプレイ＋画面レイアウト確認（後述の注意あり）
- `diag/check.js` — 起動スモークチェック（phaseとJSエラーの有無を見る）
- `SPEC.md` — 当初の仕様メモ

## ビルドとテスト

```sh
npm install                      # 初回だけ：three@0.187.0・playwright-core・wrangler を app/node_modules へ
npm run build                    # = node build.js：dist/okonomiyaki/ を作り直す
npm run ogp                      # public/ogp.png を作り直す（先に build）
npm test                         # = node tests/logic.test.js：23件、全通過が正常
npm run check                    # 起動確認（phase: title / errors: none）
```

依存はすべて `app/package.json` の devDependencies（Three.js は r187 に固定）。ブラウザでの確認（`check`・`ogp`・`tests/screens.js`）は playwright-core でインストール済みの Google Chrome（`channel: 'chrome'`）を使う。

## 仕様（ユーザーの決定事項。変えるときは先に相談すること）

- **大きさは選ばせない**：注いで広げる操作そのものが大きさ決め。大きく薄い＝焼けが早く軽く返しやすいが破れ・焦げやすい。小さく厚い＝重く焼けにくく返しにくいが満点に近づく（薄さの減点が小さい。下記の採点を参照）
- **仕上げは採点しない**（意図的な仕様）
- **X投稿ボタンは付けない**：2026-11-20に実装したが、ユーザーの判断で同日撤去した（経緯は下記）。再追加しないこと
- **焼き色**：こんがり（最適 0.68）は薄い黄金色。濃い茶色は焼きすぎ（0.88付近）から。焦げ（焼き加減0.93以上）はほぼ黒
- **採点は100点満点からの減点方式**（2026-11-21 ユーザー決定。以前の「質×挑戦度倍率（最大200点）」は廃止）。点数＝100 −返しのずれ −焼き加減 −薄さ（0点未満にはしない）。各減点は整数に丸めてから引き、結果画面の内訳（「100点から／返しのずれ／焼き加減／薄さ」）の合計と点数が必ず一致する。値は `src/logic.js` の `PENALTY` にまとめてある
  - 返しのずれ：成功（折れずに返せた）は窓の中心からのずれで 0〜15（2026-11-21 ユーザー指定で最大30→15）、惜しい（端が折れた）は 40〜70。大失敗は 0点
  - 焼き加減：表示の％（最適=100%）が 100% から 5% 離れるごとに −3（焼かなさすぎ・焼きすぎの両方向。表示と同じ整数の％で判定。96〜104% は 0、95% や 105% で −3、生焼け 50% で −30、焦げの入り口 137% で −21）。2026-11-21 ユーザー指定（1刻みの点数 3 は仮の値）
  - 薄さ：厚み3.0cm以上で 0、0.8cm以下で −30、その間は連続（例：19cm×1.8cm で −16 → 最高84点、24cm×0.9cm で −28 → 最高72点）。2026-11-21 ユーザー指定で 3.6cm→3.0cm に変更
  - 生地を広げる画面のメーターに「この厚さの最高 ◯点」を表示する
- 焼き加減ラベル：生焼け <0.35／浅め <0.55／こんがり <0.82／焼きすぎ <0.93／焦げ ≥0.93
- **焼き加減の％表示**：最適（0.68）を100%として表示し、焼きすぎると100%を超える（`donenessPercent`＝内部値÷0.68）。目安：生焼け <51%／浅め <81%／こんがり <121%／焼きすぎ <137%／焦げ ≥137%（最大147%）。内部値・判定・採点は変えていない（2026-11-21 ユーザー要望）

## 技術上の注意（必読）

- **JS文字列の中に `<a href=` を書かないこと**。Museアプリの添付プレビューが真っ黒になる（2026-11-20に切り分けで実証済み。ファイルサイズや外部URL文字列は無実）。リンクを作るときは `createElement('a')` を使う
- 配信は単一ファイルが前提。外部フォント・外部ライブラリを足さない。例外はファビコン（`public/`）だけで、無くてもゲームは動く。ビルドで `dist/okonomiyaki/` に並べるので、そこの `index.html` を開けばファビコンも出る
- `window.__oko` にテスト用フックがある（`phase`、`info()`、`discCenter()`、`audio()`（消音状態）など。起動直後の phase は `title`）。`tests/screens.js` と `diag/check.js` が使うので消さない
- **`tests/screens.js` は古い**：撤去済みのX投稿ボタンのチェック（共有チェック22件）が残っており、今の `index.html` に対して実行するとその部分だけ失敗する。使う前に共有チェックを除去すること
